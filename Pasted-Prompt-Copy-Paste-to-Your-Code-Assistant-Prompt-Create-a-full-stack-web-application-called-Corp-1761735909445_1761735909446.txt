Prompt:
 Create a full-stack web application called "Corporate Contact Finder" using Python (Flask) for the backend and HTML, CSS, JavaScript for the frontend.
🔧 Functional Requirements
Input: a <textarea> where the user can paste multiple domains, one per line.


On clicking Start Search, the backend should:


Iterate through each domain.


For each domain, perform hierarchical searches using custom search api and cx id with this ordered role list:

 ["CEO","Founder","Co-Founder","Managing Director",
 "CFO","Finance Head","Chief Financial Officer",
 "CHRO","HR Head","HR Manager","HR Executive","Talent Acquisition","HR Business Partner",
 "Marketing Head","Marketing Executive","SEO Executive","Link Builder","Digital Marketing Manager"]


For every query, use:
 site:linkedin.com/in ("<ROLE>") "<DOMAIN>"
 via custom search API.


When the first valid LinkedIn profile appears:


Extract Name, Title, LinkedIn URL.


Use Hunter.io Email Finder API with domain + full_name to get a verified email.


Save the record:

 domain | name | title | email | linkedin_url | matched_role


Then stop searching other roles for that domain and move to the next one.


If no email found for any role, mark “Not Found”.


🖥️ Frontend
Clean UI:


Textbox (placeholder: Enter domains, one per line).


Start Search / Stop Search buttons.


Progress bar or “Processing domain X of Y”.


Dynamic table for results.


Download CSV button.


Use modern responsive CSS (Tailwind or custom).


Use Fetch API for AJAX calls to /search.


⚙️ Backend (Flask)
.env variables: custom search api, cx id:  HUNTER_KEY.


Routes:


/ → serve the HTML page.


/search (POST) → receive domains array, process logic, return JSON results.


Use async or threading for parallel domain handling.


Include proper exception handling and logging.
